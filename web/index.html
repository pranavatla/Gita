Every stage of the RAG pipeline

          

          

            The production path combines Amazon Bedrock, a local vector cache,
            deterministic retrieval controls, RRF fusion, and Claude evidence reranking. Each
            stage does one narrow job well, from translating the question into
            search concepts to validating the final evidence-backed answer.
          

        


        

          

            
Corpus preparation

            

              Loads 700 Bhagavad Gita records, validates structured theme output,
              and enriches every English translation before indexing.
            

            

              load_records()
              enrich()
              validate()
            

          


          

            
Query intelligence

            

              Claude Sonnet creates four retrieval facets, including ideal evidence,
              while a controlled domain map adds source-language concepts and synonyms.
            

            

              generate_search_queries()
              expand_domain_concepts()
              Claude Sonnet 4.6
            

          


          

            
Hybrid retrieval

            

              Titan semantic search and BM25 lexical search run across the local
              700-verse cache for the original question, generated facets, and
              deterministic domain expansions.
            

            

              retrieve_candidates()
              Titan Embed v2
              local_vector_search.py
            

          


          

            
Rank fusion

            

              Reciprocal Rank Fusion merges results from every search, rewards
              repeated evidence, removes duplicate verses, and keeps the top 20 candidates.
            

            

              RRF_CONSTANT = 60
              RESULTS_PER_QUERY = 10
              MAX_RERANK_CANDIDATES = 20
            

          


          

            
Evidence reranking

            

              Claude ranks all 20 fused candidates against the natural question,
              prioritizing direct doctrinal evidence over keyword overlap.
            

            

              rerank_and_select()
              doctrinal entailment
              Claude Sonnet 4.6
            

          


          

            
Grounding selection

            

              The strongest verses in Claude's validated ranking become cited
              grounding sources. No second model decision can discard better evidence.
            

            

              ranked_verse_ids[0]
              validate_ranking()
              cited grounding
            

          


          

            
Grounded generation

            

              A final Bedrock call receives only the question and selected translation.
              If the selected evidence is weak, the app shows the closest verse
              as context instead of forcing a confident answer.
            

            

              build_context()
              generate_passage_message()
              faithfulness guardrails
              Claude Sonnet 4.6
            

          


          

            
Evaluation harness

            

              A 25-question regression set checks whether natural questions land on
              acceptable verses, so improvements can be tested instead of guessed.
            

            

              eval/rag_eval_cases.json
              evaluate_rag.py
              selected verse accuracy
            

          


          

            
Orchestration and API

            

              The final orchestration composes the grounded answer and exposes it
              through a validated FastAPI endpoint for the web experience and API consumers.
            

            

              answer_question()
              create_answer()
              trace evidence strength
