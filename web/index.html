Inside the system

Every stage of the RAG pipeline

The production path combines deterministic retrieval controls with local language models. Each stage has a narrow responsibility, from translating the question into search concepts to validating the final evidence-backed response.

01

Corpus preparation

Loads 700 Bhagavad Gita records, validates structured theme output, and enriches every English translation before indexing.

load_records() enrich() validate()
02

Query intelligence

Llama 3.1 decomposes the scenario into four semantic facets while a controlled domain map adds source-language concepts and synonyms.

generate_search_queries() expand_domain_concepts()
03

Vector retrieval

Nomic embeddings search the Chroma collection across the original question, generated facets, and deterministic domain expansions.

retrieve_candidates() nomic-embed-text ChromaDB
04

Rank fusion

Reciprocal Rank Fusion merges results from every search, rewards repeated evidence, removes duplicate verses, and keeps 50 candidates.

RRF_CONSTANT = 60 MAX_RERANK_CANDIDATES = 50
05

Neural reranking

A cached BGE cross-encoder scores every candidate against the original question and its strongest auxiliary search, then returns a global top four.

load_reranker() rerank_globally() bge-reranker-v2-m3
06

Evidence selection

A structured Llama call selects exactly one allowed verse ID. Python validation rejects missing, duplicated, or unsupported references.

select_verse_ids() validate_selection()
07

Grounded generation

A second call receives only the selected translation, separating relevance selection from message writing to prevent scenario invention.

build_context() generate_passage_message() validate_message()
08

Orchestration and API

The final orchestration composes the grounded answer and exposes it through a validated FastAPI endpoint with one-model-at-a-time execution.

generate_grounded_answer() answer_question() create_answer()
